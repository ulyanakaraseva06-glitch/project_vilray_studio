## 0. Главная установка для разработчика

Сервис должен быть понятен человеку без опыта в CAD, чертежах и профессиональных программах. Основные действия выполняются кликами по крупным карточкам, готовым шаблонам и визуальным объектам. Ручной ввод используется только для точных размеров.

Не строить универсальную архитектурную программу. Не добавлять 3D, WebGL, сложную инженерную модель, каталог производителей, авторизацию, серверную базу и коллективную работу.

MVP должен решать один сценарий:

> Пользователь создаёт схему помещения, выбирает пол или стену, назначает плитку на одну или несколько зон, получает раскладку с подрезками, двигает сетку при необходимости и формирует расчёт.

Каждый этап разработки должен оставлять рабочую версию приложения.

# 1. Коротко о продукте

«Посчитай плитку» — бесплатный визуальный планировщик раскладки керамической плитки и керамогранита.

Пользователь:

1. выбирает шаблон помещения или рисует простой контур сверху;
2. задаёт размеры помещения и высоту стен;
3. добавляет двери, окна и схематичные блоки мебели/сантехники;
4. переключается между планом, полом и стенами;
5. создаёт отдельные зоны отделки;
6. назначает каждой зоне плитку, формат и направление;
7. получает автоматические варианты раскладки;
8. двигает сетку, поворачивает плитку и корректирует отдельные элементы в ручном режиме;
9. получает расчёт по материалам, поверхностям и зонам;
10. сохраняет схему как изображение и печатный отчёт.

Сервис должен выглядеть как продукт одной линейки со «Сравни плитку»: светлый рабочий интерфейс, сиреневый акцент, крупная визуальная область, контекстная панель справа и нижний переключатель поверхностей.

# 2. Бизнес-задача

MVP должен:

- привлекать органический трафик по запросам о раскладке, подрезке и расчёте плитки;
- давать пользователю полезный результат без регистрации;
- показывать компетенции Vilray Studio в создании визуальных сервисов;
- собирать переходы на предложение разработки брендированных калькуляторов и визуализаторов;
- стать базой для будущей white-label версии для производителей, салонов и дилеров.

Основной CTA внутри сервиса:

> Создать такой инструмент для своего бренда

Подпись:

> Бесплатный сервис разработан Vilray Studio

# 3. Целевая аудитория

## 3.1. Основные пользователи

- розничный покупатель, который планирует ремонт;
- менеджер салона плитки;
- продавец строительных материалов;
- плиточник;
- дизайнер интерьера;
- замерщик;
- сотрудник производителя или дилера.

## 3.2. Уровень подготовки

Нельзя рассчитывать, что пользователь:

- понимает профессиональные термины раскладки;
- умеет рисовать планы;
- знает точные размеры всех объектов;
- будет читать длинные инструкции;
- станет разбираться в настройках до получения первого результата.

## 3.3. UX-принцип

Порядок действий должен быть очевиден по интерфейсу.

В каждый момент сервис показывает:

- что сейчас выбрано;
- что можно сделать;
- какой следующий шаг;
- что повлияет на расчёт;
- есть ли ошибка или незакрытая поверхность.

# 4. Границы MVP

## 4.1. Входит в MVP

- один проект в браузере;
- автосохранение локально;
- шаблоны помещений;
- простой редактор ортогонального контура;
- пол и стены, автоматически созданные из контура;
- двери и окна;
- схематичные блоки мебели и сантехники;
- один специальный объект «короб», создающий дополнительные поверхности;
- зоны отделки;
- несколько видов плитки в одном проекте;
- готовые форматы плитки и собственный размер;
- прямой способ укладки и смещение на 1/2;
- поворот 0°/90°;
- ширина шва;
- автоматический подбор положения сетки;
- ручное смещение всей сетки;
- ограниченная ручная правка отдельной плитки;
- расчёт целых и резаных плиток;
- расчёт площади, количества и запаса;
- расчёт коробок при введённых параметрах упаковки;
- экспорт схемы в PNG;
- печатный отчёт с сохранением в PDF средствами браузера;
- экспорт и импорт файла проекта;
- SEO-обвязка;
- события Яндекс Метрики;
- блок Vilray Studio.

## 4.2. Не входит в MVP

- 3D и перспективный вид;
- фотореалистичная визуализация;
- личный кабинет;
- облачное сохранение;
- общие ссылки на проект;
- серверная база данных;
- каталог реальных производителей;
- цены и коммерческая смета;
- автоматическая раскладка ёлочкой;
- модульные схемы из нескольких форматов;
- мозаика как набор отдельных чипов;
- криволинейные стены;
- дуги и окружности;
- сложные диагональные помещения;
- лестницы и перепады уровня;
- оптимизация повторного использования обрезков между разными зонами;
- профессиональная карта раскроя по листам;
- совместное редактирование;
- мобильное приложение.

# 5. Рекомендуемый уровень сложности

**Уровень:** статический многостраничный сайт + фронтенд-приложение со сборкой, без серверной части.

## 5.1. Стек

- Vite;
- React;
- TypeScript;
- Konva + react-konva для рабочего поля;
- обычный CSS с переменными дизайн-системы;
- Lucide React для линейных иконок;
- Vitest для тестов расчётной логики.

Не использовать:

- Next.js;
- Node.js как сервер;
- PHP;
- базу данных;
- Docker;
- Tailwind;
- Three.js;
- тяжёлый UI-kit;
- Redux.

## 5.2. Почему выбран Konva

Рабочее поле требует:

- масштабирования;
- перетаскивания;
- выделения объектов;
- сенсорных жестов;
- нескольких визуальных слоёв;
- экспорта в изображение;
- устойчивой работы с большим числом прямоугольников плитки.

Ручная реализация этих функций на DOM/SVG увеличит объём кода и число ошибок. Konva используется только для редактора. Остальной интерфейс остаётся обычным React/CSS.

## 5.3. Хранение данных

- текущее состояние проекта: React store/reducer;
- автосохранение: `localStorage`;
- явное сохранение: скачиваемый JSON-файл проекта;
- загрузка проекта: импорт этого JSON-файла;
- изображения пользователя в постоянное хранилище не сохраняются в MVP.

# 6. Основной пользовательский сценарий

## 6.1. Первое открытие

В рабочей области показываются крупные карточки шаблонов:

- Прямоугольная ванная;
- Квадратное помещение;
- Узкий санузел;
- Г-образное помещение;
- Помещение с выступом;
- Нарисовать самому.

Ниже:

- «Открыть сохранённый проект»;
- короткая подпись: «Размеры можно изменить после выбора».

Пользователь не должен сначала заполнять форму.

## 6.2. После выбора шаблона

Сразу появляется план сверху. На стенах показаны размеры. Справа открывается блок «Размеры помещения» с готовыми вариантами и точными значениями.

Контекстная подсказка:

> Проверьте размеры. Затем добавьте дверь или выберите поверхность.

## 6.3. Добавление объектов

Пользователь нажимает карточку объекта и затем кликает по плану.

Объект создаётся с типовым размером. Его можно:

- перетащить;
- повернуть на 90°;
- растянуть за ручки;
- выбрать размер из готовых вариантов;
- удалить.

## 6.4. Выбор поверхности

Пользователь:

- кликает по полу;
- кликает по линии стены на плане;
- либо выбирает поверхность в нижней ленте.

Рабочая область переключается на плоский вид выбранной поверхности.

## 6.5. Зоны

На поверхности уже есть базовая зона на всю доступную площадь.

Пользователь может добавить:

- нижнюю часть стены;
- верхнюю часть стены;
- вертикальную полосу;
- горизонтальную полосу;
- зону душевой;
- фартук;
- произвольный прямоугольник.

Границы зоны меняются перетаскиванием.

## 6.6. Плитка

Пользователь выбирает:

- визуальный образец;
- формат;
- ориентацию;
- шов;
- способ раскладки.

После выбора нажимает:

> Подобрать раскладку

Сервис показывает три карточки вариантов:

- Ровные края;
- Меньше подрезок;
- От выбранного угла.

## 6.7. Ручная настройка

После выбора варианта пользователь может:

- перетаскивать сетку плитки;
- нажимать стрелки точной подстройки;
- повернуть всю раскладку;
- открыть скрытый режим «Ручная правка»;
- выбрать отдельную плитку и сдвинуть, повернуть или удалить её.

## 6.8. Расчёт

Кнопка «Расчёт» открывает панель с итогами, не закрывая рабочее поле.

Пользователь видит:

- поверхности;
- зоны;
- материалы;
- целые плитки;
- резаные плитки;
- количество по раскладке;
- площадь покрытия;
- отход;
- запас;
- коробки, если заполнена упаковка.

Новый сервис должен восприниматься как продукт той же линейки, но не копировать экран буквально.

## 8.1. Сохранить

- тонкую верхнюю панель;
- логотип слева;
- светлый фон приложения;
- крупную визуальную область слева/по центру;

- нижнюю ленту переключателей;
- сиреневые активные состояния;
- тонкие серые границы;
- небольшие скругления;
- компактные интерфейсные кнопки;
- спокойную плотность элементов;
- небольшую брендированную плашку Vilray внизу панели.

## 8.2. Заменить

В «Сравни плитку» справа находится каталог. В «Антиобрезке» справа находится контекстная библиотека:

- шаблоны помещений;
- объекты;
- виды зон;
- форматы плитки;
- варианты раскладки;
- расчёт.

Нижние миниатюры интерьеров заменить миниатюрами поверхностей:

- План;
- Пол;
- Стена 1;
- Стена 2;

- Короб: боковина.

# 10. Правая панель / нижняя мобильная панель

Основные вкладки:

1. **План**
2. **Объекты**
3. **Зоны**
4. **Плитка**
5. **Раскладка**
6. **Расчёт**

Вкладки показываются контекстно. Например, «Зоны» и «Раскладка» неактивны, пока не выбрана поверхность.

Внизу панели всегда находится блок:

> Что дальше

Примеры:

- «Выберите шаблон помещения»;
- «Проверьте размеры»;
- «Выберите пол или стену»;
- «Добавьте зону или назначьте плитку на всю поверхность»;
- «Выберите вариант раскладки»;
- «Расчёт готов».

# 11. Модуль помещения

## 11.1. Шаблоны

Обязательные шаблоны:

| ID | Название | Описание |
|---|---|---|
| rectangle | Прямоугольник | 4 стены |
| square | Квадрат | равные стороны |
| narrow | Узкий санузел | вытянутый прямоугольник |
| l-shape | Г-образное | 6 стен |
| projection | С выступом | прямоугольный выступ |
| custom | Своя форма | пользователь ставит точки |

Каждая карточка содержит:

- мини-схему;
- название;
- типовой размер;
- кнопку выбора не показывать: вся карточка кликабельна.

## 11.2. Типовые размеры

Для каждого шаблона дать 3–4 готовых размера и вариант «Свой».

Пример для прямоугольной ванной:

- 1,5×1,7 м;
- 1,7×2,0 м;
- 2,0×2,0 м;
- 2,0×2,5 м;
- свой размер.

Высота стен:

- 2,5 м;
- 2,7 м;
- 3,0 м;
- свой размер.

## 11.3. Редактор контура

В MVP поддерживаются только прямые сегменты и углы 90°.

Пользователь может:

- перетаскивать вершину;
- нажать на размер стены и ввести точное значение;
- добавить прямоугольный выступ;
- удалить выступ;
- вернуть шаблон к исходному виду.

Ограничения:

- от 4 до 12 стен;
- размер стороны от 300 мм до 15 000 мм;
- высота от 1 800 до 4 500 мм;
- контур не должен самопересекаться;
- помещение должно быть замкнутым.

## 11.4. Внутренние единицы

Все размеры хранить целыми числами в миллиметрах.

В интерфейсе:

- помещение: метры и сантиметры;
- плитка: сантиметры;
- точные подрезки: миллиметры.

# 12. Двери и окна

## 12.1. Добавление

Пользователь выбирает карточку «Дверь» или «Окно» и кликает по стене.

Элемент автоматически привязывается к стене.

## 12.2. Дверь

Параметры:

- ширина: 600 / 700 / 800 / 900 мм / свой;
- высота: 2000 / 2100 мм / своя;
- смещение от левого края стены;
- направление открывания используется только как схема на плане;
- вычитается из площади стены.

## 12.3. Окно

Параметры:

- ширина;
- высота;
- высота подоконника;

## 12.4. Поведение

- при уменьшении стены элемент автоматически сдвигается внутрь;

- на плоском виде стены проём виден как вырез.

- Горизонтальная полоса;

# 17. Раскладка

## 17.1. Способы укладки MVP

- Прямая;
- Со смещением 1/2.

Не добавлять 1/3, диагональ, ёлочку и модульную схему до отдельного согласования.

## 17.2. Ориентация

- Горизонтально;
- Вертикально;

Для квадратной плитки кнопка поворота не показывается.

## 17.3. Пресеты положения

- Плитка по центру;
- Шов по центру;
- От левого края;
- От правого края;
- От нижнего края;
- От выбранного угла.

## 17.4. Автоматические варианты

Кнопка:

> Подобрать раскладку

Результат: до трёх карточек с миниатюрой и показателями.

### Вариант A: «Ровные края»

Приоритет:

1. убрать узкие подрезки;
2. сделать противоположные края близкими по размеру;
3. уменьшить отход.

### Вариант B: «Меньше подрезок»

Приоритет:

1. уменьшить количество резаных плиток;
2. уменьшить отход;
3. не допускать подрезок ниже критического значения.

### Вариант C: «От выбранного угла»

Приоритет:

1. начать с целой плитки или заданного отступа;
2. сохранить направление пользователя;
3. показать размеры крайних подрезок.

## 17.5. Критическая подрезка

Настройка:

- не уже 50 мм;
- не уже 100 мм;
- не уже 1/3 плитки;
- своё значение.

По умолчанию: не уже 50 мм.

Критические элементы:

- подсвечиваются оранжевым;
- показываются в списке предупреждений;
- не блокируют расчёт.

## 17.6. Ручное смещение сетки

Пользователь может:

- перетаскивать всю сетку на рабочем поле;
- двигать по X/Y кнопками ±1 мм и ±10 мм;
- вернуть выбранный автоматический вариант;
- включить/выключить привязку.

На мобильном сетка двигается только после включения режима «Двигать раскладку», чтобы не конфликтовать с перемещением сцены.

## 17.7. Ограниченная ручная правка плитки

Режим спрятан под кнопкой «Ручная правка».

В режиме можно:

- выбрать отдельную плитку или подрезку;
- сдвинуть её;
- повернуть на 90°;
- удалить;
- восстановить;
- вернуть всю зону к автоматической раскладке.

Правила:

- при наложении показывать красную область;
- при образовании незакрытой области показывать предупреждение;
- ручные изменения учитываются в количестве;
- свободное масштабирование плитки запрещено;
- изменение размера плитки выполняется только через материал.

# 18. Математика и расчёт

## 18.1. Общие правила

- все вычисления выполняются в миллиметрах и квадратных миллиметрах;
- округление в интерфейсе не должно менять исходные данные;
- площадь выводится до 0,01 м²;
- размеры подрезок выводятся до 1 мм;
- расчёт пересчитывается после каждого подтверждённого изменения;
- во время перетаскивания допускается облегчённый предпросмотр, полный пересчёт запускается после отпускания.

## 18.2. Полезная площадь поверхности

```text
полезная площадь = площадь поверхности
                 − площадь дверей/окон
                 − площадь исключённых объектов
                 − площадь зон «Без плитки»
```

Для стен вычитаются проёмы.

Для пола вычитаются только объекты с включённым параметром «Не укладывать плитку под объектом».

## 18.3. Шаг сетки

```text
шаг X = ширина плитки + ширина шва
шаг Y = высота плитки + ширина шва
```

Шов отображается как промежуток между прямоугольниками плитки и не входит в площадь материала.

## 18.4. Генерация плиток

Для каждой зоны:

1. получить ограничивающий прямоугольник;
2. с учётом origin X/Y создать сетку ячеек;
3. для смещения 1/2 сдвигать каждый второй ряд на половину шага X;
4. пересечь прямоугольник плитки с геометрией зоны;
5. вычесть проёмы и исключённые области;
6. классифицировать элемент;
7. сохранить видимую геометрию подрезки для рендера и отчёта.

## 18.5. Классификация

- **целая плитка:** видимая площадь равна площади плитки с допуском 0,5 мм по краям;
- **резаная плитка:** видимая площадь больше нуля, но меньше полной;
- **не используется:** пересечение отсутствует или меньше технического допуска.

## 18.6. Количество

Для каждой зоны считать:

- целые плитки;
- резаные плитки;
- всего плиток по раскладке;
- покрытая площадь;
- закупочная площадь по числу плиток;
- отход.

```text
всего по раскладке = целые + резаные
закупочная площадь = всего по раскладке × площадь одной плитки
отход = закупочная площадь − покрытая площадь
процент отхода = отход / покрытая площадь × 100%
```

## 18.7. Материал в нескольких зонах

Количество по материалу складывается из всех зон этого материала.

В MVP остатки от резки между независимыми зонами автоматически не переиспользуются. Это нужно прямо указать в отчёте:

> Расчёт учитывает плитки по каждой раскладке отдельно и не оптимизирует перенос обрезков между зонами.

## 18.8. Запас

Готовые варианты:

- без дополнительного запаса;
- +5%;
- +10%;
- +15%;
- своё значение.

По умолчанию: +10%.

```text
рекомендуемое количество = ceil(количество по раскладке × (1 + запас / 100))
```

## 18.9. Коробки

Если задано количество плиток в коробке:

```text
коробки = ceil(рекомендуемое количество / плиток в коробке)
```

Если задано только м² в коробке:

```text
коробки = ceil(рекомендуемая площадь / м² в коробке)
```

## 18.10. Автоподбор origin

Для каждого кандидата положения сетки рассчитать:

- число критических подрезок;
- минимальную ширину крайней подрезки;
- число резаных плиток;
- процент отхода;
- разницу между противоположными краями.

Рекомендуемый порядок оценки:

1. сильный штраф за подрезку ниже порога;
2. максимизация минимальной подрезки;
3. минимизация количества резаных плиток;
4. минимизация отхода;
5. симметрия краёв.

Перебирать origin в пределах одного шага плитки с дискретностью:

- 5 мм для обычных размеров;
- 2 мм для плитки менее 150 мм;
- ограничивать число вариантов, чтобы расчёт стандартной поверхности занимал менее 500 мс на среднем ноутбуке.

# 22. Undo / Redo

История обязательна.

В историю входят:

- изменение контура;
- размеры;
- добавление/удаление объекта;
- перемещение объекта;
- создание/изменение зоны;
- назначение материала;
- изменение раскладки;
- ручная правка плитки.

Не добавлять в историю:

- масштаб сцены;
- положение камеры;
- открытие панели;
- hover;
- временный drag до отпускания.

Хранить не менее 50 действий.

# 38. Правила для Codex

1. Сначала прочитать документ целиком.
2. Не начинать со всех модулей сразу.
3. Выполнять этапы по порядку.
4. После каждого этапа остановиться и выдать отчёт.
5. Не добавлять сервер, базу, авторизацию и облачное хранение.
6. Не менять выбранный стек без предупреждения.
7. Не добавлять UI-kit и Tailwind.
8. Не превращать интерфейс в многошаговый мастер.
9. Не переносить основной сценарий на отдельные страницы.
10. Не усложнять ввод: сначала карточки и пресеты, потом точное значение.
11. Не использовать временные заглушки вместо расчётной логики после этапа 4.
12. Разделить визуальный слой и расчётную геометрию.
13. Покрыть геометрию и расчёт unit-тестами.
14. Не хранить сгенерированные плитки в проектном JSON.
15. Не встраивать рекламные pop-up внутри рабочего сценария.
16. Сохранять визуальную связь со «Сравни плитку».
17. Все ограничения и компромиссы фиксировать в `CHANGELOG.md`.
18. Новую библиотеку добавлять только при явной экономии сложности.
19. Если расчёт не может считаться точным из-за ограничения MVP, показать это пользователю и описать в документации.
20. Публичная сборка должна работать на обычном статическом хостинге после загрузки содержимого `dist/`.

# 39. Финальный результат MVP

Готовый сервис должен позволять человеку без специальной подготовки:

1. открыть страницу;
2. выбрать готовое помещение;
3. поправить размеры;
4. добавить дверь и основные предметы;
5. выбрать пол или стену;
6. разделить поверхность на зоны;
7. назначить несколько видов плитки;
8. получить раскладку;
9. убрать неудачные узкие подрезки;
10. увидеть количество материала;
11. сохранить схему и отчёт;
12. перейти на сайт Vilray Studio при интересе к собственному сервису.

Главный критерий качества: первый расчёт должен получаться без чтения отдельной инструкции и без ручного заполнения длинной формы.
