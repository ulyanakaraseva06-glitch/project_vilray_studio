# SEO и GEO-стратегия

## 1. Цель

Сервис должен получать органический трафик по задачам расчёта, раскладки и подрезки плитки. Редактор сам по себе недостаточен: поиску и AI-системам нужны статические страницы с понятными ответами, примерами и ссылкой на интерактивный инструмент.

## 2. Архитектура поиска

- главная и тематические страницы доступны как готовый HTML;
- редактор расположен отдельно по `/app/`;
- каждая тематическая страница открывает редактор с подходящим пресетом;
- текст, заголовки, FAQ и пример расчёта находятся в исходном HTML;
- URL не зависят от hash-routing;
- страница остаётся полезной без запуска редактора.

## 3. Кластеры запросов

### Расчёт количества

- расчёт плитки онлайн;
- калькулятор плитки;
- сколько плитки нужно;
- рассчитать плитку на пол;
- рассчитать плитку на стену;
- расчёт плитки для ванной;
- количество коробок плитки;
- запас плитки на подрезку.

### Раскладка

- раскладка плитки онлайн;
- схема раскладки плитки;
- раскладка плитки в ванной;
- раскладка крупноформатной плитки;
- раскладка плитки 60×120;
- плитка по центру или шов по центру;
- раскладка от угла;
- как избежать узких подрезок.

### Профессиональные сценарии

- схема плитки для плиточника;
- карта подрезок;
- расчёт плитки с дверями и окнами;
- расчёт нескольких видов плитки;
- раскладка плитки по зонам.

## 4. Страницы запуска

На старте создать 10–12 сильных страниц. Не генерировать сотни почти одинаковых посадочных страниц.

Каждая страница должна содержать:

- точный H1;
- короткий ответ на задачу в первом экране;
- CTA «Открыть расчёт»;
- пример с конкретными размерами;
- пояснение алгоритма;
- ограничения;
- FAQ;
- связанные страницы;
- подпись об авторстве Vilray Studio;
- дату обновления.

## 5. Метаданные

Для каждой страницы:

- уникальный `title`;
- уникальный `description`;
- один H1;
- canonical;
- Open Graph;
- `lang="ru"`;
- понятный slug;
- изображения с width/height и alt;
- хлебные крошки, если страница не главная.

Главная:

**Title:** `Расчёт и раскладка плитки онлайн — Посчитай плитку`  
**Description:** `Нарисуйте помещение, разложите плитку на полу и стенах, проверьте подрезки и рассчитайте количество плитки и коробок. Бесплатно, без регистрации.`  
**H1:** `Рассчитайте плитку и проверьте раскладку онлайн`

## 6. Структурированные данные

Использовать только данные, которые видны пользователю:

- `SoftwareApplication` или `WebApplication` на страницах продукта;
- `Organization` для Vilray Studio;
- `BreadcrumbList` на внутренних страницах;
- `FAQPage` только для реально показанного FAQ;
- `Article` для подробных инструкций.

Разметку валидировать отдельно для Google и Яндекса. Не обещать расширенный сниппет: его показ решает поисковая система.

## 7. Sitemap и robots

- генерировать `sitemap.xml` при сборке;
- включать только canonical-страницы с кодом 200;
- не добавлять query-параметры редактора;
- указать sitemap в `robots.txt`;
- не блокировать CSS, JS и изображения, нужные для рендера;
- служебные тестовые страницы закрыть `noindex` или не публиковать.

## 8. Внутренняя перелинковка

- главная ссылается на основные сценарии;
- каждая страница содержит 3–5 релевантных ссылок;
- страницы форматов ссылаются на общую раскладку и расчёт;
- страницы расчёта ссылаются на подрезки и запас;
- рекламные ссылки на проекты Vilray отделены от навигации по знаниям.

## 9. GEO: подготовка к AI-поиску

GEO здесь означает Generative Engine Optimization.

Специальные «AI-хаки» не использовать. Основа та же, что и у качественного SEO:

- страница индексируется и доступна без авторизации;
- ответ дан прямо под заголовком;
- определения и формулы написаны однозначно;
- есть разобранный пример;
- указаны ограничения расчёта;
- автор и организация понятны;
- дата обновления видна;
- контент отличается собственным инструментом и расчётной методикой;
- каждый смысловой блок имеет стабильный якорь;
- важные ответы не спрятаны только в canvas или изображении.

Формат answer block:

```text
Короткий ответ
2–4 предложения с прямым решением.

Как считается
Формула или последовательность действий.

Пример
Размер помещения, формат, шов, полученный результат.

Ограничения
Что сервис не учитывает и что проверить на объекте.
```

Не включать `llms.txt` как обязательный элемент MVP. Не создавать специальную AI-разметку, которой нет в поддерживаемых стандартах.

## 10. Региональная оптимизация

Сервис полезен по всей России и не требует городских посадочных страниц.

Разрешено:

- указать организацию Vilray Studio и реальные контакты;
- связать сайт с карточкой организации, если она существует;
- использовать регион в контактах и Organization-разметке;
- создавать региональную страницу только при наличии отдельного предложения, адреса или локального контента.

Запрещено:

- создавать десятки страниц «расчёт плитки в городе N» с одинаковым текстом;
- подменять полезный контент списком географических ключей.

## 11. Контентная достоверность

- не обещать абсолютную точность;
- не публиковать выдуманные проценты отхода как универсальную норму;
- отделять запас пользователя от отхода текущей раскладки;
- примеры должны воспроизводиться в сервисе;
- массовая AI-генерация страниц без нового результата запрещена.

## 12. Технический контроль перед публикацией

- View Source содержит H1, основной текст и ссылки;
- canonical корректен;
- sitemap отдаёт 200;
- robots не блокирует страницы;
- 404 возвращает настоящий код 404;
- нет дублирования со slash/non-slash;
- мобильная версия проходит базовую проверку;
- страницы не загружают редактор до необходимости;
- JSON-LD проходит валидаторы;
- отправлены sitemap в Google Search Console и Яндекс Вебмастер;
- подключены Яндекс Метрика и при необходимости Google Analytics/Search Console.

## 13. Метрики SEO/GEO

- индексируемые страницы;
- показы и клики по кластерам;
- доля переходов в `/app/`;
- завершённые расчёты из органики;
- страницы, которые цитируются или дают переходы из AI-поиска;
- брендовые запросы «Посчитай плитку»;
- клики на Vilray Studio и смежные проекты.
