# Тестирование и приёмка

## 1. Unit-тесты

Обязательные модули:

- преобразование единиц;
- площадь ортогонального полигона;
- вычитание прямоугольных проёмов;
- генерация прямой сетки;
- генерация смещения 1/2;
- классификация целой плитки и подрезки;
- определение критической подрезки;
- сравнение origin-кандидатов;
- расчёт отхода;
- расчёт запаса;
- расчёт коробок;
- объединение итогов по материалу;
- миграция импортируемого проекта.

## 2. Контрольные сценарии

### A. Простая стена

- поверхность 2400×2400 мм;
- плитка 600×600 мм;
- шов 0 мм;
- ожидается 16 целых плиток.

### B. Стена с дверью

- поверхность 3000×2700 мм;
- дверь 800×2100 мм;
- проверить вычитание проёма и покрытие вокруг него.

### C. Формат 60×120

- стена 2400×2700 мм;
- шов 2 мм;
- сравнить плитку и шов по центру;
- вариант с микрофрагментом не может быть лучшим.

### D. Две зоны

- основная зона и вертикальная полоса;
- два материала;
- итоги разделены и объединяются по material ID.

### E. Мобильный интерфейс

- ширина 360 px;
- рабочее поле видно при открытой панели 45%;
- все основные действия доступны без горизонтального скролла.

### F. Импорт

- корректный schemaVersion 1 открывается;
- неизвестное поле игнорируется безопасно;
- битый JSON даёт понятную ошибку;
- опасная строка не вставляется как HTML.

## 3. UX-проверка

Дать сервис человеку без инструкции и проверить:

- нашёл ли он шаблон;
- понял ли, как открыть стену;
- выбрал ли плитку;
- нашёл ли перемещение сетки;
- открыл ли расчёт;
- понял ли разницу между отходом и запасом.

Критический критерий: пользователь получает первый визуальный результат без чтения справки.

## 4. SEO-проверка

- основной контент виден в View Source;
- у страниц уникальные метаданные;
- canonical не ведёт на `/app/`;
- sitemap содержит только публичные страницы;
- robots доступен;
- JSON-LD валиден;
- внутренние ссылки обычные `<a href>`;
- 404 возвращает 404;
- не публикуются тестовые страницы.

## 5. Производительность

- первая статическая страница не загружает редактор;
- редактор не блокируется аналитикой и рекламой;
- стандартный пересчёт выполняется без заметной задержки;
- drag остаётся плавным;
- большое число плиток переключает режим отображения без падения;
- экспорт не зависает на стандартном проекте.

## 6. Доступность

- кнопки имеют подписи;
- активное состояние различимо без цвета;
- контраст текста достаточен;
- focus видим;
- Enter подтверждает поле;
- Escape закрывает панель;
- browser zoom не запрещён;
- зоны нажатия не меньше 44 px.

## 7. Критерии готовности MVP

MVP принят, когда:

- все обязательные сценарии работают;
- расчётные тесты проходят;
- проект сохраняется и импортируется;
- desktop и mobile работают в одном экране;
- SEO-страницы собраны статически;
- sitemap и метаданные сформированы;
- реклама управляется конфигом;
- аналитика не отправляет геометрию пользователя;
- подготовлен отдельный архив `frontend-public`;
- документация запуска и деплоя соответствует сборке.
